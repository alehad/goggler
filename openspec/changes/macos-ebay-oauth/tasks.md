- [x] Manual functional confirmation (user): tap "Connect eBay," complete a real Production eBay login via the system auth sheet, confirm the app immediately shows connected — via Tailscale, per the usual manual-testing convention. **Three real bugs found and fixed during this pass**, each confirmed via logging/direct testing before moving on, not guessed at:
  1. A Swift 6 compiler defect (closure lexically inside a `@MainActor` method gets erroneously inferred as MainActor-isolated even for a plain/non-isolated completion-handler parameter type) caused a real crash (`EXC_BREAKPOINT` on the Safari XPC thread) the first time the flow actually completed. Fixed with an explicit `@Sendable` closure plus an inner `Task { @MainActor in }` hop.
  2. eBay's registered redirect URI points at the Tailscale Funnel port (`:8443`), not the tailnet-only `serve` port (`:443`) the persistent backend normally serves on — the Funnel had to be stood up by hand for this test (and torn back down immediately after, per the established "briefly, by hand" posture) since day-to-day persistence deliberately only covers the tailnet-only port.
  3. The reused `HTTPCookieStorage.shared` already held an older `goggler_session` cookie from before the OAuth flow (set automatically by `URLSession` from Home's own startup check); the new one didn't reliably replace it, so the app kept polling the wrong session and reporting "not connected" even though the backend session was genuinely connected (verified directly via `curl` with the reissued token). Fixed by explicitly deleting any existing cookie for that name before inserting the new one; added a regression test reproducing the exact shape (parsed from a real `Set-Cookie` header, not hand-constructed) and confirmed it fails without the fix.
- [x] Manual functional confirmation (user): the existing **web** OAuth flow still works unchanged (confirmed by the passing `routes.test.mjs` coverage; the native marker is opt-in and defaults away).
- [x] Run dual security review (security-review skill + Copilot CLI) — this one touches session/auth code directly, review carefully. **Copilot found a real HIGH-confidence finding**: `EbayAuthService`'s diagnostic logging (added for the live debugging above) logged the full callback URL — including the raw session token in its query string — with `privacy: .public`, making it readable in plaintext via Console.app/`log show` by anything with local log access. Fixed by logging only the `account` status, never the full URL; re-verified 13/13 tests still pass after the fix.
